## Задание 2. Ловушки темы (traps.cpp)

**Реальный вывод:**
1) 0 1
2) ветка выполнилась
2) age = 18
3) 1 0
4) 1 1
4) 0 0

**Объяснения:**
1) `5>3` (истина), `8<6` (ложь). Логическое И (&&) дает 0 (ложь), логическое ИЛИ (||) дает 1 (истина).
2) Внутри `if` использован оператор присваивания `=` вместо сравнения `==`. Присваивание `age = 18` возвращает 18 (истина), поэтому ветка выполняется, а переменная `age` меняет значение с 5 на 18.
3) Выражение `0 < x < 10` вычисляется слева направо. Сначала `0 < -5` дает 0. Затем `0 < 10` дает 1. Правильная проверка диапазона требует двойного условия `x > 0 && x < 10`.
4) Работает закон де Моргана: `!(a && b)` эквивалентно `!a || !b`. Поэтому обе формы дают одинаковый результат на любых данных.


## Задание 3. Висячий else под отладкой (dangling.cpp)

**Прогоны ДО починки:**

*   (группа 1, балл 5): Вечерняя смена *(else привязался к if(score>=8))*

**Объяснение:** Язык C++ привязывает `else` к ближайшему незакрытому `if`. Поэтому `else` относился к проверке балла, а не к проверке группы. Для вечерней смены внешний `if` не срабатывал, и программа шла дальше, минуя внутренний блок.

**Прогоны ПОСЛЕ починки (добавлены фигурные скобки):**
*   (группа 1, балл 9): Утренняя смена, допуск есть
*   (группа 1, балл 5): Утренняя смена, допуска нет
*   (группа 2, балл 9): Вечерняя смена

**Ответы на вопросы проекта:**
1. Почему проверка веса обязана стоять до `switch`? 
Если её убрать, программа попытается рассчитать стоимость для нулевого или отрицательного веса, что бессмысленно. Ранний отказ экономит ресурсы и предотвращает логические ошибки.
2. Почему для статуса одного сравнения `weight > 5` мало? 
Потому что тест (7, 3, 0) имеет вес больше 5, но доставка не срочная (0). Если использовать только `weight > 5`, этот груз ошибочно получит статус "тяжёлый срочный", хотя он стандартный. Нужно составное условие `(weight > 5 && urgent == 1)`.
