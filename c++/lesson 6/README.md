2. Объяснение результатов
Почему 0.3 не равно 0.3?

В C++ тип double хранит числа в двоичном формате (стандарт IEEE 754). Числа вроде 0.1 и 0.2 в двоичной системе являются бесконечными периодическими дробями (как 1/3 в десятичной). Компьютер обрезает их до ближайшего возможного значения, поэтому в памяти 0.1 + 0.2 превращается в 0.30000000000000004. При сравнении через == это дает 0 (ложь).

Почему cout выводит 0.333333, а не больше знаков?

По умолчанию std::cout выводит ровно 6 значащих цифр. Чтобы увидеть хвост, нужно использовать std::setprecision из библиотеки iomanip.

Объяснение «испорченной» прямой формулы:

Формула перевода в Фаренгейты: F = C * 9 / 5 + 32.

Если записать int scale = 9 / 5, компилятор выполнит целочисленное деление (отбросит дробную часть) и scale станет равен 1 (а не 1.8).

Для C = 36.6 расчет идет: 36.6 * 1 + 32 = 68.6.

Чтобы этого избежать, нужно использовать double scale = 9.0 / 5.0 или 1.8.
