# Отчет по ПР17. Создание меню различных видов (VIEW)

## 1. Пять «пунктов меню» (Список видов)
В базе созданы следующие виды (все с префиксом `v_`):
1. **v_price** *(проекция)* — показывает только названия инструментов, цены и категории (срез колонок).
2. **v_open** *(фильтр)* — показывает только невозвращённые выдачи (`return_date IS NULL`).
3. **v_rentals_full** *(соединение)* — выдача с расшифровкой имен клиента и инструмента (JOIN трех таблиц).
4. **v_client_deposits** *(агрегат)* — сколько выдач и на какую сумму залогов приходится на каждого клиента (`GROUP BY`).
5. **v_open_full** *(вид поверх вида)* — невозвращённые выдачи, но сразу с именами клиентов и инструментов (строится на базе `v_rentals_full`).

## 2. Родной способ изменения вида в моей СУБД (SQLite)
В SQLite команды `ALTER VIEW` и `CREATE OR REPLACE VIEW` **не поддерживаются**. 
При попытке их выполнения СУБД выдает синтаксические ошибки:
*   `ALTER VIEW v_price AS SELECT name FROM tools;` -> `OperationalError: near "VIEW": syntax error`
*   `CREATE OR REPLACE VIEW ...` -> `OperationalError: near "OR": syntax error`

**Родной способ изменения вида в SQLite** — это полное удаление старого вида и создание нового с тем же именем:
```sql
DROP VIEW v_price;
CREATE VIEW v_price AS SELECT name, price_per_day, category FROM tools;
